## このドキュメント群の運用ルール(アジャイル前提)

このプロジェクトは個人開発・1人体制のため、フルウォーターフォールではなく **土台だけ先に固め、詳細は実装直前にイテレーティブに詰める** 方針を取る。

- **企画書・要件定義書**: 大きく変わらない前提なので基本的に固定。変更する場合は差分がわかるようにその都度更新する。
- **外部設計書(02_design/)**: 機能ドメインごとにファイルを分割している。1機能を実装するタイミングでそのファイルだけ詳細化・更新すればよく、他ファイルへの影響を気にしなくてよい設計にしている。
- **未決事項**: 各設計書に書ききれない/確定できない論点は [02_design/99_open-issues.md](./02_design/99_open-issues.md) に集約する。実装着手時にここを見て、詰まっていなければ先に決めてから着手する。
- 更新履歴はファイル内に持たず、git の履歴に任せる。
